# Финальный проект. Инженер по тестированию плюс

Проект состоит из двух частей:

1. Работа с базой данных через консоль.
2. Автотест API для проверки получения заказа по треку.

## Часть 1. Работа с базой данных

Для проверки данных необходимо подключиться к БД scooter_rent через консоль с помощью psql.

Команда для подключения к базе данных:
psql -U morty -d scooter_rent

##Подготовка тестовых данных
Перед выполнением SQL-запросов были подготовлены тестовые данные:

1. На стенде был создан заказ.
2. Через API был создан курьер.
3. Через API заказ был принят курьером.

После принятия заказа курьером заказ перешёл в состояние inDelivery = true. Это позволило проверить данные в базе.

### Задание 1

Нужно вывести логины курьеров и количество заказов, которые находятся в доставке.

SQL-запрос:
SELECT c."login", COUNT(o."track") AS orders_count
FROM "Couriers" c
JOIN "Orders" o ON c."id" = o."courierId"
WHERE o."inDelivery" = true
GROUP BY c."login";
Результат:
 login | deliveryCount 
-------+---------------
 anton |             2
(1 row)

Запрос показал, что у курьера anton есть 2 заказа в доставке.

### Задание 2

Нужно вывести трекеры заказов и их статусы.

Статусы рассчитываются по условиям:

- если finished = true, статус равен 2;
- если cancelled = true, статус равен -1;
- если inDelivery = true, статус равен 1;
- во всех остальных случаях статус равен 0.

SQL-запрос:
SELECT "track",
  CASE
    WHEN "finished" = true THEN 2
    WHEN "cancelled" = true THEN -1
    WHEN "inDelivery" = true THEN 1
    ELSE 0
  END AS status
FROM "Orders";
Результат:
 track  | status 
--------+--------
 305348 |      1
 305348 |      1
(2 rows)

Запрос показал, что оба заказа находятся в статусе 1, то есть в доставке.

## Часть 2. Автотест API

Автотест проверяет, что по треку заказа можно получить данные о заказе.

Для автотеста ручная подготовка данных не требуется. Тест сам создаёт заказ через API, сохраняет его трек и выполняет запрос на получение заказа по этому треку.

### Сценарий автотеста

1. Выполняется запрос на создание заказа.
2. Из ответа сохраняется номер трека заказа.
3. Выполняется GET-запрос на получение заказа по треку.
4. Проверяется, что код ответа равен 200.
